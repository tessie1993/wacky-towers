## Summary

Piece geometry (cube offsets) is extracted from the imported block GLBs by a headless tool script into a generated `shape_bank.tres`, so code never hand-copies shapes and the art stays the source of truth. Rotation uses a precomputed integer table of the 24 cube rotations plus per-shape distinct-orientation lists, so rotating a piece is an array lookup with no floats.

## Context

### Problem Statement

The game has 67 shapes in 10 families (Piece Set GDD), modelled in Blender and imported as GLBs per block set (`candy_toy`, `neon_voxel`, more coming). The sim needs integer cube offsets, bounding boxes, distinct orientations and spawn orientation for each. Hand-typing them would drift from the art; reading GLBs at runtime is slow and needs the scene tree.

### Current State

`block_post_import.gd` makes each piece scene's root the pivot-cube empty with one `MeshInstance3D` per cube on integer offsets. `block_set_import_test.gd` checks cube counts against a hand-copied table (marked `ponytail:` to be replaced by the shape data file).

### Constraints

- User decision: extract offsets from the block GLBs, not from Blender.
- Mirror images are different shapes (Piece Set rule 4); only proper rotations (24).
- Rotation is around the pivot cube (Piece Set rule 9).

### Requirements

- Every shape: `shape_id`, offsets, bounding box, family, hue, motif, spawn orientation, distinct orientation list (GDD F4: `24 / |G|`).
- Rotation lookup in O(1), integer only, identical on every device.
- Every block set must match the bank (test).

## Decision

### Coordinate frame

The GDD frame is y-up, the same as Godot. Blender's z-up to glTF's y-up conversion `(x, y, z) → (x, z, −y)` is a proper rotation, so imported offsets are already in the game frame and the GDD coordinate tables match up to rotation. **No remapping code.** Shapes are compared in canonical form, so the authored rotation in Blender does not matter.

### Extraction

- `tools/asset-pipeline/extract_shape_bank.gd` (headless `-s` script, run after `--import`) loads one reference block set (default `candy_toy`, a tool argument), reads each piece scene's cube children, rounds positions to `Vector3i`, and checks: face-connected, no duplicates, no two shapes equal up to rotation.
- Writes `res://assets/data/shapes/shape_bank.tres` (`ShapeBank` with `Array[ShapeDef]`). Geometry fields are regenerated; hand fields (`display_name`, `family`, `hue_id`, `motif`, `tags`) are kept from the existing file on regenerate, keyed by `shape_id`.
- `shape_id` comes from the file name (`blk_<set>_<shape_id>.glb`).
- The test suite checks every other block set against the bank (same canonical offsets per `shape_id`). New block sets need no code.

### Why `.tres` here (levels are JSON, ADR-0005)

The bank is generated by our own tool, shipped inside the `.pck` at `res://`, and never loaded from a user path. Player levels refer to shapes only by `shape_id` strings, which the validator checks against the bank. `.tres` gives typed fields, inspector editing of hand fields, and UIDs. Untrusted data never goes through `ResourceLoader` (ADR-0005).

### Orientation math

- `Orientations` (static, `RefCounted` with static vars) builds the 24 rotation matrices once, as integer 3×3 (rows of `Vector3i`), by breadth-first closure from the identity using 90° turns about +x, +y, +z, in that order. The BFS order fixes each orientation's index (0 = identity), so indices are stable everywhere.
- `TURN[o][axis][dir] -> o'`: precomputed transition table (24 × 3 × 2).
- `ShapeDef` stores, per shape:
  - `offsets_by_orient: Array` (of `Array[Vector3i]`) — offsets for each of the 24 orientations, rotated about the pivot (offset 0,0,0).
  - `distinct_of: PackedInt32Array` (24) — maps any orientation to its distinct class; `distinct_count` (GDD F4 check).
  - `spawn_orient: int` — smallest bounding extent along +y; ties broken by lowest index.
  - `bbox_by_orient: Array[Vector3i]` (24) and `min_by_orient` for spawn centring.
- Rotating a piece = `o = TURN[o][axis][dir]`, then the collision check uses `offsets_by_orient[o]`. View-relative rotation (camera picks which world axis is "tilt"/"roll", Movement & Rotation) maps the input to a world axis before this lookup.
- Wall kicks are Movement & Rotation's job; they use these offsets.

### Canonical form

Canonical key = for each of the 24 orientations, translate offsets so the minimum corner is (0,0,0), sort, serialise; take the lexicographically smallest. Used by the extractor (rotation-duplicate check) and the GDD acceptance test (Screw-Left ≠ Screw-Right).

### Architecture

```
 blk_<set>_<id>.glb ─import─▶ piece scene (pivot root + cube MeshInstance3D)
                                      │ extract_shape_bank.gd (headless)
                                      ▼
            res://assets/data/shapes/shape_bank.tres  (ShapeBank → ShapeDef[])
                                      │ loaded once
             ┌────────────────────────┼─────────────────────────┐
         BoardSim / Movement     Spawner / Validator      View (mesh + preview per shape_id)
                     ▲
           Orientations (24 int matrices, TURN table)
```

### Key Interfaces

```gdscript
class_name ShapeDef extends Resource
@export var shape_id: StringName
@export var display_name: String
@export var family: StringName
@export var hue_id: int                  # palette index (assets/data/palette.json); board stores this id
@export var motif: StringName
@export var tags: PackedStringArray
@export var cube_count: int
@export var offsets_by_orient: Array  # of Array[Vector3i] (no nested typed arrays)
@export var bbox_by_orient: Array[Vector3i]
@export var distinct_of: PackedInt32Array
@export var distinct_count: int
@export var spawn_orient: int

class_name ShapeBank extends Resource
@export var shapes: Array[ShapeDef]
func get_shape(id: StringName) -> ShapeDef     # null if unknown
func has_shape(id: StringName) -> bool

class_name Orientations extends RefCounted
const COUNT := 24
static func turn(o: int, axis: int, dir: int) -> int
static func apply(o: int, v: Vector3i) -> Vector3i
```

### Implementation Guidelines

- Generate tables lazily on first use, or once in a static initialiser; they are tiny (24 × 3 × 2 ints).
- The extractor is a tool, not runtime code; it lives in `tools/asset-pipeline/`.
- Replace `CUBE_COUNTS` in `block_set_import_test.gd` with a read of the bank (removes the existing `ponytail:` note).
- Custom shapes inside player levels: not supported now; levels pick from the bank. Add a `shapes` section to the level schema when a design needs it (it would go through the same canonical/connectivity checks).

## Alternatives Considered

### Alternative 1: Hand-typed shape table in code or JSON
- **Cons**: Drifts from the art; 67 shapes × errors.
- **Rejection Reason**: The GLBs already encode the truth.

### Alternative 2: `Basis` / quaternion rotation at runtime
- **Cons**: Floats, rounding, slower, device-dependent edge cases.
- **Rejection Reason**: 24 integer matrices cover every case exactly.

### Alternative 3: Export from Blender (`wt_shapes` in `blocks.blend`)
- **Rejection Reason**: User decision — no Blender step in the build.

### Alternative 4: Remap axes (x, z, −y) in code
- **Rejection Reason**: The conversion is a rotation; canonical comparison makes it irrelevant.

## Consequences

### Positive
- New shapes = model + export + rerun extractor; no code. New block sets are checked automatically.

### Negative
- A generated file in the repo that must be regenerated when shapes change (test fails if stale).

### Neutral
- About 67 × 24 small offset arrays in memory (< 200 KB).

## Risks

| Risk | Probability | Impact | Mitigation |
|------|------------|--------|-----------|
| Bank stale after a GLB edit | Medium | Medium | Test compares every set to the bank |
| A block set authored with a different pivot | Low | Medium | Canonical comparison; pivot only matters for rotation feel, flagged by test if offsets differ |
| Hand fields lost on regenerate | Low | Low | Extractor merges by `shape_id` |

## Migration Plan

1. Write `extract_shape_bank.gd`, generate the bank, commit it.
2. Switch `block_set_import_test.gd` from `CUBE_COUNTS` to the bank.

**Rollback plan**: The bank is plain data; a hand-maintained file would satisfy the same `ShapeBank` interface.

## Validation Criteria

- [ ] Extractor produces all bank shapes; `distinct_count` matches GDD F4 (O = 3, I = 3, T = 12, Big Cube = 1).
- [ ] All 24 canonical rotations of each shape give the same key; Screw-Left ≠ Screw-Right; Twist-Left ≠ Twist-Right.
- [ ] `turn` four times about one axis returns the start orientation; the 24 matrices are distinct with determinant +1.
- [ ] Every block set matches the bank.
