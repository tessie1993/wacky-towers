## Workflow rules (every task)

1. **One fresh agent per chunk.** A task that lists several CH ids gets one agent per CH. Same-file chains are the exception and run as ONE agent in order: `board_state.gd` 050+054, `movement.gd` 051+053, `board_sim.gd` 064 → 066 → 068.
2. **Tests first.** The writer writes the gdUnit4 test, then the code. The writer does not launch Godot.
3. **Stage, then integrate.** Writers write into a `_staging/` folder next to the target (it has a `.gdignore`), with tests in `tests/unit/<system>/_staging/`. Only the integrator moves files into place.
4. **Integrator = godot-ai / godot-mcp-toolkit in the live editor.** Wait for `production/session-state/EDITOR_FREE` and take the lock. Move the staged parts in, scan, `logs_read`, fix parse errors. Run **only that chunk's** gdUnit4 test file through the in-editor plugin (never the full suite). For scenes: `project_run` + `input_simulate`, `editor_screenshot` to `production/qa/evidence/<task-id>/`. Release the lock. Report in ≤5 lines.
5. **No headless runs on the project.** Headless Godot is only for throwaway scripts in the scratchpad.
6. Writers report in ≤5 lines and never paste code. The lead flips the CH status rows. No commits unless the user asks.
7. Orchestrator graphs live only in `src/game/` (ADR-0010). beehave is for staging only: anything that changes the board is a `RuleRuntime` rule (ADR-0011). Sim/core never imports a plugin.

**Legend.** Size: S ≤ 1 day, M 1–2 days, L 2–3 days (agent-days including integration). **WAIT-GDD** = the design doc is being revised right now (modified in git, wave 2): do not start until the designer marks it done. **WAIT-BLENDER** = Blender is not open yet. Batch = parallel batch; a task starts when its own depends-on are done, even if the rest of its batch is not.

**GDDs being revised now (WAIT-GDD set):** `movement-rotation`, `fall-drop-lock`, `layer-clearing`, `level-goals-fail-states`, `hud`, `touch-controls`, `mechanics-module`, `level-specific-mechanics`, `twist-library`, and the UI screens `ux/{README,title,settings,profile-select,ui-theme,...}`, plus the new `points-system` and the review-flagged `scoring-stars`.
